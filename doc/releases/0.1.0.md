## Resumen Ejecutivo

La version 0.1.0 de Associated marca el primer release funcional del ERP ligero para colectividades espanolas. Este release cubre el ciclo completo desde el scaffold inicial del proyecto hasta un sistema desplegado en produccion, incluyendo backend (NestJS 11 + Prisma 7 + PostgreSQL 18), frontend (React 19 + Vite 7 + Mantine 8) e infraestructura Docker para produccion.

El desarrollo se organizo en dos grandes fases: **Backend Fase 1** (febrero-marzo 2026) con la implementacion de 10 casos de uso en 4 Bounded Contexts (Identity, Membership, Treasury), y **Frontend Fase 1** (marzo 2026) con 6 tareas principales que cubren identidad visual, autenticacion, planes de cuota, suscripciones, alta de socios y bajas/rehabilitaciones. Posteriormente se realizo una auditoria exhaustiva del frontend, una reescritura completa de la suite de tests, y el despliegue a produccion en VPS.

El sistema implementa una arquitectura Modular Monolith con CQRS, Domain Events y multi-tenancy (base de datos separada por tenant), con cifrado AES-256-GCM para datos sensibles (IBAN) y autenticacion JWT multi-tenant.

## Caracteristicas Principales

### Backend (BC-Identity)

- **UC-001 Provision de nuevo tenant:** Saga de 10 pasos con rollback compensatorio idempotente. Crea base de datos, usuario PostgreSQL, ejecuta migraciones y siembra roles.
- **UC-002 Autenticacion multi-tenant:** User aggregate con lockout temporal, JWT strategy, 5 endpoints auth, guards globales (JwtAuthGuard, PermissionsGuard, SuperadminGuard).
- Credenciales per-tenant encriptadas (AES-256-GCM) con EncryptedSecret VO y TenantCredentialsModule global.

### Backend (BC-Membership)

- **UC-006 Gestion de ficha de socio:** 6 Value Objects (PersonalData, ContactData, IdentityDocument con validacion DNI/NIE mod-23, BankDetails con validacion IBAN mod-97, MemberNumber, CustomFields), cifrado IBAN, 4 endpoints REST.
- **UC-007 Gestion de estados de socio:** Maquina de estados con transiciones validadas, StatusHistory, eventos MemberStatusChanged.
- **UC-008 Gestion de tipos de socio:** MemberType aggregate, RulesEvaluator, plantillas por colectividad, 7 endpoints REST.
- **UC-010 Gestion de ejercicios fiscales:** FiscalYear aggregate, DateRange VO, CQRS handlers, controller REST.
- **UC-011 Proceso de alta simplificado:** Flujo incremental 3 pasos con guardado de progreso.
- **UC-013 Baja y reingreso de socios:** Leave, Expulsion, Reinstatement con conservacion de numero de socio.

### Backend (BC-Treasury)

- **UC-017 Gestion de planes de cuota:** FeePlan aggregate, Amount VO en centavos, Periodicity.
- **UC-018 Gestion de suscripciones de cuota:** MemberAccount aggregate, FeeSubscription entity, Discount VO multiplicativo, 6 endpoints REST.
- **UC-019 Generacion masiva de cargos periodicos:** Charge entity, GenerateChargesHandler.
- **UC-021 Registro de cobros:** Payment entity, RegisterPaymentHandler, ReceiptGeneratedEvent, PDF receipt service.

### Frontend

- **Task 0 Brand Setup:** Theme Mantine completo con paleta brand, tipografia Inter, spacing, shadows y 11 component defaults. 6 logos SVG.
- **Task 1 UC-002 Autenticacion multi-tenant:** Login con flujo dual (directo/multi-tenant), selector tenant, AuthProvider con refresh transparente, rutas protegidas, AppLayout con sidebar y dark mode.
- **Task 2 UC-017 Planes de cuota:** CRUD completo con tabla filtrable, formulario condicional RECURRING/ONE_TIME, vinculacion tipos socio, plantillas, inactivacion protegida.
- **Task 3 UC-018 Suscripciones de cuota:** Selector de plan, descuentos multiplicativos con formula paso a paso, cambio plan, timeline historico, exenciones.
- **Task 4 UC-011 Alta simple de socio:** Wizard 3 pasos con validacion DNI mod 23, selector tipo socio con validacion edad, verificacion email con debounce, confirmacion con cargo inscripcion.

## Mejoras y Correcciones Destacadas

### Mejoras de Calidad

- Eliminados 70 warnings ESLint en workspace API: `as any` reemplazados por tipos concretos.
- Reescrita suite completa de tests frontend: factories, helpers de render, MSW handlers (92 archivos, 19806 inserciones).
- Migrado stack frontend a Zod 4 + react-hook-form (desde Zod 3.25 + @mantine/form).
- Regla ESLint `no-restricted-syntax` (ERROR) para casteos inseguros sobre campos Prisma Json.
- Optimizado test suite backend: eliminados ~87 tests redundantes y fortalecidas ~22 assertions debiles.
- Plugin SWC (vitest-plugin-swc) para soporte de metadata de decoradores NestJS (transform 78s → 2.5s).

### Correcciones Criticas

- **Race condition auth:** `applyLoginResponse` ahora async con `await getCurrentUser()` - permisos disponibles antes de renderizar sidebar.
- **Loop infinito tests frontend:** `watch()` sin argumentos en personal-data-step.tsx generaba nuevo objeto cada render.
- **Prisma 7 P1012:** URL no permitida en datasource del schema - migrado a `prisma.config.ts`.
- **DomainExceptionFilter:** No registrado como APP_FILTER - errores de dominio devolvian 500 en vez de status correctos.
- **Interceptor Axios:** Secuestraba errores 401 de login (solo excluia /auth/refresh, corregido para excluir todos los /auth/).
- **Pipeline CI:** `prisma generate` antes de lint/tests (resuelve 30 fallos por modulos no encontrados).

## Lecciones Aprendidas

1. **Prisma 7 es ESM-only:** Requiere `prisma.config.ts` para configuracion en lugar de inline en schema. Driver adapter obligatorio (`@prisma/adapter-pg`). Multi-schema requiere un config por schema con `--config` en CLI.

2. **Campos Json de Prisma:** No necesitan `JSON.stringify()` al guardar ni `JSON.parse()` al leer. Prisma auto-serializa. La doble serializacion causaba datos corruptos en permisos.

3. **Race conditions en auth SPA:** El orden de operaciones es critico: (1) login, (2) await getCurrentUser, (3) renderizar UI. Sin el await, el sidebar renderiza sin permisos.

4. **`watch()` de react-hook-form sin argumentos:** Retorna un nuevo objeto en cada render, causando loops infinitos en useEffect. Siempre especificar campos: `watch('fieldName')`.

5. **vitest + NestJS:** Sin SWC plugin, los decoradores de NestJS no se procesan correctamente. El transform de TypeScript puro tarda ~78s vs ~2.5s con SWC.

6. **Despliegue Docker en VPS:** nginx en host (no en Docker) es la opcion correcta para un unico dominio con Let's Encrypt. El contenedor web solo sirve la SPA, no gestiona SSL.

7. **CI pipeline con Prisma:** `prisma generate` debe ejecutarse ANTES de lint y tests. Sin los clientes generados, 30+ imports fallan.
